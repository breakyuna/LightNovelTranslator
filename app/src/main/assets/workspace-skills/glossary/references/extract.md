# 术语提取与整理

本流程用于提取术语、发现遗漏或系统整理术语规则。执行前读取 `references/rule.md`，按其中的收录、身份、字段和覆盖判据判断对象与方案。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 优先用 `list_items`、`read_item`、`search_items` 和本包脚本做程序化批量探查；仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 自启发循环

- 从任务目标、已有材料、调查结果和覆盖缺口中提炼可用于后续探查的特征模式或具体线索，称为 `种子`。
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子。
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称为 `自启发循环`。

## 种子账本

种子账本是逻辑调查状态，可保存在 `work/TASKNAME-seeds.json`。原生工具没有通用的工作区文件直读或直接覆盖：写入用 `prepare_workspace_changes` 生成 `work/` 下的变更提案；更新已有文件时，在变更脚本的只读 `workspace-files.jsonl` 材料中核对当前 SHA-256；读取以工作区文件界面、用户提供的内容和对话中已公开的记录为准。未收到 `workspace_change_status` 回执前，不得声称账本已保存。

- 账本记录实时调查状态，必须每轮更新，禁止跨轮补写。
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`。
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`；尚需补查或受阻的种子保持 `false`。
- 同轮处理多个种子、搜索或采样均计为一轮，`completedRounds` 在本轮完成时增加 `1`。

账本示例：

```jsonc
{
  "completedRounds": 1,
  "seeds": {
    "1": [
      {
        "pattern": "检索姓名和称谓中的「ヴァレン」，结合语境核验家族归属、称谓指向与固定译名。",
        "consumed": false
      }
    ]
  }
}
```

## 循环执行

### 循环入口

从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。用 `project_statistics` 了解条目总量，用 `list_items` 按 `after_id` 分页选取区域，再用 `read_item` 读取目标原文。

### 循环轮次

每次按顺序完整执行以下步骤称为一个 `循环轮次`：

1. 轮次开始时，从循环入口开始，或读取账本中未消耗的种子。
2. 根据种子中的特征模式进行探查，形成审查结论，准备规则或文本变更方案但暂不提交。
3. 回看探查与处理过程，提炼新的种子，更新 `completedRounds` 和已消耗种子的状态。
4. 写入或更新账本。

重复执行循环轮次，直到同时满足：

1. 任务目标全部完成。
2. 本轮没有新的种子产生，账本中所有种子均已消耗。
3. 包含入口轮次在内，至少进行过 3 个轮次的循环探查，即 `completedRounds >= 3`。

轮次不足且没有未消耗种子时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。

## 领域参考

循环入口与后续种子调查均按下文取证、判断和验收，相关模式可以合批调查。将证据位置、对象结论、实际处理范围和未决事项按轮号保存到工作记录，并同步关系图与规则方案。

### 种子探查

种子探查可以从以下方向展开，但无需局限于此。错误、正确案例和不同处理方式都可以提供线索：

- **发现候选**：从正文、姓名、首次登场、定义和特殊用法中提取可检索的线索，调查对象身份与收录资格。
  - 例如：发现“将魔力储存在「星核」中”的描述后，检索 `星核`，结合定义与用途核验是否属于作品特有概念。
- **扩展同类**：从已确认对象中提取命名或使用特征，调查其他可能需要收录的同类对象。
  - 例如：确认 `紅蓮の印` 是技能名后，检索 `の印`，结合获得、发动等语境调查其他技能及其固定译名。
- **核验差异**：发现同名异指、同词异译或相似名称处理不同时，调查差异是否符合各自身份与语境。
  - 例如：发现 `ルナ` 分别译为“露娜”和“月神”后，调查命中语境，核验是否指向同一实体，以及译法是否需要适用条件。
- **追查关联**：确认新的身份、别名、所属或命名体系后，调查受该发现影响的其他对象与规则。
  - 例如：确认 `エレン` 与 `ノア・ヴァレン` 是姐弟后，检索 `ヴァレン`，核验其他姓名、家族称谓的成员归属与指向。
- **检查边界**：从词根新增命中、反例和覆盖缺口中提取线索，调查规则的适用条件与必要分支。
  - 例如：角色名 `セラ` 同时命中普通词 `セラミック` 后，调查这类命中能否依靠局部语境区分，核验条件说明或收窄方案。

### 取证与对象判断

- **条目原文与姓名**：主要用 `read_item` 读取原文和现有译文；需要全量字面命中时，用本包 `scripts/main.js` 扫描固定修订的 `source` 与 `name_source` 快照，按判断目的选择计数或完整位置并核对完整性，调用方法见 `references/scripts.md`。
- **条目语境**：当前工具没有 `queryItemContexts` 或 `@lg/workspace/item-contexts`。用 `list_items` 的 `after_id` 取命中条目附近的条目，再逐个 `read_item` 读取必要语境；跨文件或结构不清时，用 `list_workspace_materials`/`read_workspace_material` 读取可用的文本原稿。
- **姓名与表记**：`read_item` 不返回独立姓名数组；姓名证据从正文、`search_items` 命中、脚本扫描的 `name_source` 字段和 `project_text_policy` 的现有规则取得。
- **PDF**：PDF 页流程已冻结。本流程不读取页面数据集、不按页码取证，也不使用 `pages` 契约。

### 关系图与规则方案

对象记录、Mermaid 实体关系图与规则方案共用同一份事实依据，随身份、关系、译名和覆盖变化同步更新：

- 节点表示已确认实体，标签使用当前译名并保留辨认所需的原名或别名，已确认但没有关系的实体使用孤立节点。
- 连线表示工程证据支持的关系与方向，节点和连线均关联对象记录与证据，未确认关系加入待查记录。
- 核验同一实体、别名、包含、所属和命名体系等关系，需要字符关系线索时使用本包 `scripts/relations.js`，调用方法见 `references/scripts.md`。
- 按 `references/rule.md` 的“选择词根与精简规则”制定完整方案，保存对象到规则的覆盖对应、采用的最短安全自然词根、必要分支及其证据。

### 成果验收

- **调查完整**：实际范围与证据相符，全部发现对象均有结论，后续问题已处理或有具体未决说明。未决对象仍计入未完成的覆盖目标。
- **关系可信**：范围内已确认实体与关系均纳入图，检查重复节点、错误连接、关系冲突、译名分歧和证据缺口，核对孤立对象是否遗漏关联线索。
- **规则成立**：按 `references/rule.md` 的“验收最终集合”检查对象覆盖与命中安全，身份、字段、译名、合并拆分与关系证据一致。
- **成果一致**：关系图、对象记录、规则方案与覆盖对应一致，节点和连线可追溯到证据，图能正确显示且展示范围明确。

调查范围尚未覆盖、验收发现遗漏、不一致或待核验事实时，补充或更新种子，继续调查。

## 交付

首先，在回复中展示实体关系图：

- 最多展示 3 张关系图，每张不超过 10 个实体，优先呈现关键关系。
- 按家族、组织或命名体系等实际关系拆图，标签使用简短译名，跨图实体保持同名。

然后，合并各轮次方案，通过 `prepare_text_policy` 准备完整策略替换：先读取 `project_text_policy` 的基准指纹和全部现有规则，保留应继续生效的规则，再加入本次 `TERM` 规则。用户审批后用 `policy_proposal_status` 核对回执。提供种子账本和业务工作记录的可读取位置，并说明：

- 实际调查范围与覆盖程度，区分程序扫描、实际阅读和实体判断。
- 主要发现、收录与取舍依据，以及采用的词根和必要分支。没有发现术语时，说明调查依据。
- 已确认实体、名称、身份未明候选与规则各自的数量。
- 任务完成或受阻的情况及未决事项，区分拟议方案、待审批提案与实际提交回执，关系图与对应成果保持一致。
