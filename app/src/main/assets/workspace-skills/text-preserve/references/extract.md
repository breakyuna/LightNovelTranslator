# 文本保护提取与整理

本流程用于提取保护结构、发现遗漏或系统整理保护规则。执行前读取 `references/rule.md`，按其中的保护资格、字段、表达式安全和覆盖判据判断对象与方案。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 优先用 `list_items`、`read_item`、`search_items` 和本包扫描脚本做程序化批量探查；仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

## 自启发循环

- 从任务目标、已有材料、调查结果和覆盖缺口中提炼可用于后续探查的特征模式或具体线索，称为 `种子`。
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子。
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称为 `自启发循环`。

## 种子账本

种子账本是逻辑调查状态，可保存在 `work/TASKNAME-seeds.json`。原生工具没有通用的工作区文件直读或直接覆盖：写入用 `prepare_workspace_changes` 生成 `work/` 下的变更提案；更新已有文件时，在变更脚本的只读 `workspace-files.jsonl` 材料中核对当前 SHA-256；读取以工作区文件界面、用户提供的内容和对话中已公开的记录为准。未收到 `workspace_change_status` 回执前，不得声称账本已保存。

- 账本记录实时调查状态，必须每轮更新，禁止跨轮补写。
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`。
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`；尚需补查或受阻的种子保持 `false`。
- 同轮处理多个种子、搜索或采样均计为一轮，`completedRounds` 在本轮完成时增加 `1`。

账本示例：

```jsonc
{
  "completedRounds": 1,
  "seeds": {
    "1": [
      {
        "pattern": "检索与已确认占位符 {name} 相似的花括号片段，结合来源格式与语境核验替换用途、参数变体与自然语言边界。",
        "consumed": false
      }
    ]
  }
}
```

## 循环执行

### 循环入口

从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。用 `project_statistics` 了解条目总量，用 `list_items` 按 `after_id` 分页选取区域，再用 `read_item` 读取目标原文。

### 循环轮次

每次按顺序完整执行以下步骤称为一个 `循环轮次`：

1. 轮次开始时，从循环入口开始，或读取账本中未消耗的种子。
2. 根据种子中的特征模式进行探查，形成审查结论，准备规则或文本变更方案但暂不提交。
3. 回看探查与处理过程，提炼新的种子，更新 `completedRounds` 和已消耗种子的状态。
4. 写入或更新账本。

重复执行循环轮次，直到同时满足：

1. 任务目标全部完成。
2. 本轮没有新的种子产生，账本中所有种子均已消耗。
3. 包含入口轮次在内，至少进行过 3 个轮次的循环探查，即 `completedRounds >= 3`。

轮次不足且没有未消耗种子时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。

## 领域参考

循环入口与后续种子调查均按下文取证、判断和验收，相关模式可以合批调查。将证据位置、对象结论、实际处理范围和未决事项按轮号保存到工作记录，并同步关系图与规则方案。

### 种子探查

种子探查可以从以下方向展开，但无需局限于此。错误、正确案例和不同处理方式都可以提供线索：

- **发现候选**：从定界符、标签、控制前缀、转义和固定标记中提取可检索的线索，调查结构用途与保护资格。
  - 例如：发现 `ようこそ、{name}さん！` 后，结合来源格式与语境核验 `{name}` 是否为运行时替换的姓名占位符。
- **扩展同类**：从已确认结构的参数、前后缀、位置和组合方式中提取特征，调查其他可能需要保护的变体。
  - 例如：确认 `{name}` 是占位符后，调查其他花括号片段、重复槽位及不同文件中的参数用法。
- **核验差异**：发现相似结构保护方式不同、译文结构损坏或相关线索时，调查差异是否符合各自用途与语境。
  - 例如：发现 `<br>` 被保留而 `<br/>` 被改写后，核验两种写法的格式用途与规则覆盖。
- **追查关联**：确认新的包含、重复或覆盖关系后，调查受该发现影响的其他结构与规则。同时处理术语时，将结构槽位中的名称交由术语流程调查。
  - 例如：确认容器标记包围可翻译正文后，调查开始与结束标记的组合、嵌套及各自覆盖规则。
- **检查边界**：从新增命中、自然语言反例和覆盖缺口中提取线索，调查表达式的收窄条件与必要分支。
  - 例如：`<[^>]+>` 同时命中标签和比较表达式后，调查实际标签名与参数形态，核验可独立保护的安全子结构。

### 取证与对象判断

- **结构来源与用途**：从 `read_item` 的原文、`project_text_policy` 的现有 `PROTECT` 规则和用户材料取得证据，实际阅读代表片段与必要语境。缺少格式或用途事实时，用 `project_summary` 找到资产，再按 `list_workspace_materials`/`read_workspace_material` 读取可用的文本原稿；打包 EPUB 等二进制材料不能直接读取，以导入条目为准。
- **表达式命中**：使用本包扫描入口对每条表达式独立编译，完整扫描声明范围的原始 `item.source`，保存命中的条目、行、片段、文件和文本类型分布，核对命中证据完整性。调用方法见 `references/scripts.md`，字段契约见 `references/scan-contract.md`。
- **安全与边界**：按 `references/rule.md` 的“单条表达式安全”核验每类命中与自然语言反例，表达式收窄或拆分后重新取得受影响证据。尚无安全表达式的必要结构记为未决，保存已尝试方案、失败原因与继续所需的格式事实。
- **证据完整性**：当前工具没有预生成的 `warnings` 数据集。不要引用 `ws.contract`、`queryItemContexts` 或 `workspace_run`；命中与覆盖率只以实际扫描和阅读结果为准。

### 关系图与规则方案

对象记录、Mermaid 结构与规则覆盖关系图与规则方案共用同一份事实依据，随结构、表达式和覆盖变化同步更新：

- 节点表示保护结构或规则，标签使用可辨认的结构样例或简短规则说明，尚无安全规则覆盖的必要结构标为未决。
- 连线表示工程证据支持的包含、重复或覆盖关系与方向，节点和连线均关联对象记录与证据，未确认关系加入待查记录。
- 核验结构与表达式的关系，按 `project_text_policy` 中规则的 `source` 对相同表达式分组，结合实际匹配行为判断重复与合并，调用示例见 `references/scripts.md`。
- 按 `references/rule.md` 的“结构与规则覆盖”和“单条表达式安全”制定完整方案，保存结构到规则的覆盖对应、安全分支及其证据，追溯合并、拆分和删除后各成员的去向。

### 成果验收

- **调查完整**：实际范围与证据相符，全部发现对象均有结论，后续问题已处理或有具体未决说明。未决对象仍计入未完成的覆盖目标。
- **关系可信**：范围内必要结构与最终规则均纳入图，检查重复对象、错误连接、关系冲突和覆盖缺口，包含、重复及覆盖关系均有证据。
- **规则成立**：按 `references/rule.md` 核验保护资格、字段与表达式安全，各表达式具备独立安全证据；合并、拆分和删除后必要结构仍有安全覆盖，成员去向可追溯。扫描使用 JavaScript 正则，最终规则由原生策略校验，不能用扫描通过代替规则通过。
- **成果一致**：关系图、对象记录、规则方案与覆盖对应一致，节点和连线可追溯到证据，图能正确显示且展示范围明确。

调查范围尚未覆盖、验收发现遗漏、不一致或待核验事实时，补充或更新种子，继续调查。

## 交付

首先，在回复中展示结构与规则覆盖关系图：

- 最多展示 3 张关系图，每张不超过 10 个节点，优先呈现关键关系。
- 按结构的包含、重复或覆盖等实际关系拆图，标签使用简短结构样例或规则说明，跨图对象保持同名。

然后，合并各轮次方案，通过 `prepare_text_policy` 准备完整规则替换：先读取 `project_text_policy` 的基准指纹和全部现有规则，保留应继续生效的规则，再加入本次 `PROTECT` 规则。用户审批后用 `policy_proposal_status` 核对回执。提供种子账本和业务工作记录的可读取位置，并说明：

- 实际调查范围与覆盖程度，区分程序扫描、实际阅读和结构判断。
- 主要发现、保护与取舍依据，以及采用的表达式、安全分支和代表性边界证据。没有发现保护结构时，说明调查依据。
- 已确认结构、用途未明候选与规则各自的数量，按结构和规则身份分别去重，区分扫描命中次数与命中条目数。
- 任务完成或受阻的情况及未决事项，区分拟议方案、待审批提案与实际提交回执，关系图与对应成果保持一致。
