# 文本保护规则判据

`PROTECT` 规则保护翻译中必须逐字保留的非语义控制符、占位符和格式结构。先根据结构身份和逐字保留的需求判断保护资格，再核验表达式能否安全覆盖。

## 资格与字段

修改字段前，核对目标规则的保护结构与字段含义。表达式变化时，按“单条表达式安全”核验受影响的命中与边界。

原生 `ProjectTextPolicy` 使用以下字段：

|字段|含义|
|---|---|
|`id`|规则稳定身份，不能为空，不能重复|
|`kind`|本流程使用 `PROTECT`|
|`source`|匹配内容；`regex=false` 时按字面量，`regex=true` 时按正则源码|
|`target`|保护规则通常留空；其他规则类型按各自用途使用|
|`note`|供用户辨认规则的简短说明，含义改变时同步更新|
|`enabled`|是否参与运行时策略|
|`regex`|是否按正则解释 `source`|
|`case_sensitive`|是否区分大小写|
|`scope`|保护规则使用 `BODY`；只有 `TERM` 规则可使用 `NAME` 或 `BOTH`|

- 已确认的控制结构若不能由普通翻译稳定保持，应当保护。自然语言与普通词义按翻译处理。
- 次数、当前损坏、既有规则使用时间、生效模式和零命中提供辅助证据，不能单独决定保护资格。
- 用 `asset_id`、`item_id` 和文件路径关联工程材料，按表达式确定运行时匹配条件；当前工具没有独立的 `file_path` 数据集契约。
- 原生 `TERM` 规则不允许 `regex=true`；保护规则可以使用正则，但必须通过 `prepare_text_policy` 的原生校验。

## 结构与规则覆盖

保护结构与规则分别记录，一个结构可以由多个安全分支覆盖，一条规则也可以覆盖多个已核验形态。分别为结构的包含、重复关系及规则的覆盖关系取证。判断表达式是否等价或可以合并时，核对实际匹配行为。合并、拆分和删除须保留必要结构的覆盖与成员去向。

## 单条表达式安全

通过本包 `scripts/main.js` 取证（调用见 `references/scripts.md`），每条表达式独立以 JavaScript `giu` 编译，在按 `\n` 拆行的原始 `item.source` 上核验。扫描结果只是证据，不是最终规则执行；保存 `PROTECT` 规则时，原生策略使用 RE2/J 语法和程序/分组上限校验，二者语法并不完全等价。

合法表达式需要匹配非空、必须保持的结构，避免无界通配、危险回溯和吞掉自然语言正文。编译通过后，完整扫描声明范围，核验命中形态、位置、边界和反例。表达式改变后重新取得受影响证据。

宽候选同时命中结构与正文时，依据实际标签名、前缀、参数字符集、定界符、长度和位置缩小或拆分。安全子结构可以独立形成规则，剩余对象继续判断。保护需求存在但任何安全表达式都无法隔离时，说明缺少的格式事实或所需人工边界。

非法或产生零长度匹配的既有规则需要修正或删除，其原本保护的对象仍需确认去向。最终集合由已验证规则组成，必要结构有覆盖或明确未决。最终规则必须通过 `prepare_text_policy` 校验；校验失败时修正表达式，不能绕过或伪报成功。

## 判断示例

|候选与证据|处置|
|---|---|
|`\{player_name\}` 的命中都是角色名占位符|直接保护|
|`\{\d+\}` 覆盖编号占位符且未吞正文|直接保护|
|`\{.*\}` 同时覆盖占位符与正文|按真实参数形态缩小或拆分|
|`^` 或 `.*?` 产生零长度匹配|另选能安全覆盖必要结构的表达式|
|`<[^>]+>` 命中 HTML 标签和比较表达式|按已确认标签形成安全分支|
|结构与自然语言形式完全相同，正则无法区分|保留明确未决并说明需要的格式事实|
