# `items` 审校

本流程用于检查、审校和修正工程中的已有或拟议译文。适用 TXT、EPUB 及其他导入为条目的文本；PDF 页流程已冻结，本参考不处理页面。

## 任务范围

按用户要求确定任务范围：

- 用户未限定范围时，覆盖当前工程全文。
- 用户指定问题时，围绕该问题及其必要关联开展调查。
- 优先用 `search_items`、`list_items`、`project_statistics` 做程序化批量探查；仅在用户明确要求或无法程序化批量探查时逐条进行语义分析。

当前工具没有预生成的 `warnings` 数据集。不要引用 `ws.contract`、`queryItemContexts`、`workspace_run` 或 `apply`，也不要把不存在的警告记录当作入口或证据。

## 自启发循环

- 从任务目标、已有材料和调查结果中提炼可用于后续探查的特征模式或具体线索，称为 `种子`。
- 根据种子发现下一批需要调查的目标，再从调查与处理结果中提炼新的种子。
- 重复前述过程，直到任务目标完成且所有种子均已消耗，称为 `自启发循环`。

## 种子账本

种子账本是逻辑状态，可保存在 `work/TASKNAME-seeds.json`。原生工具没有通用的工作区文件直读或直接覆盖：写入用 `prepare_workspace_changes` 的脚本在 `work/` 下生成变更提案，更新已有文件时在变更项提供当前 `baseSha256`；读取以工作区文件界面、用户提供的内容和对话中的已公开记录为准；未收到 `workspace_change_status` 回执前，不得声称账本已保存。

- 账本是实时状态机而非汇总报告，必须每轮更新，禁止跨轮补写。
- 轮次从 `1` 开始，新增或需要重新调查的种子设为 `consumed = false`。
- 完成取证、结果处理和后续种子提炼后，将目标种子设为 `consumed = true`；尚需补查或受阻的种子保持 `false`。
- 同轮处理多个种子、搜索或采样均计为一轮，`completedRounds` 在本轮完成时增加 `1`。

账本示例：

```jsonc
{
  "completedRounds": 1,
  "seeds": {
    "1": [
      {
        "pattern": "筛选原文同时含「毎日」和「最大」的条目，核验译文是否保留每日数量上限及其适用对象。",
        "consumed": true
      }
    ]
  }
}
```

## 循环执行

### 循环入口

没有警告入口时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。用 `project_statistics` 了解总量，用 `list_items` 按 `after_id` 分页选取区域，再用 `read_item` 读取目标。

### 循环轮次

每次按顺序完整执行以下步骤称为一个 `循环轮次`：

1. 轮次开始时，从循环入口开始，或读取账本中未消耗的种子。
2. 根据种子中的特征模式，用 `search_items` 和 `read_item` 探查，形成审查结论；需要修正时准备 `prepare_item_changes` 或 `prepare_text_policy` 提案，但未获批准前不提交。
3. 回看探查与处理过程，提炼新的种子，更新 `completedRounds` 和已消耗种子的状态。
4. 写入或更新账本。

重复执行循环轮次，直到同时满足：

1. 任务目标全部完成。
2. 本轮没有新的种子产生，账本中所有种子均已消耗。
3. 包含入口轮次在内，至少进行过 3 个轮次的循环探查，即 `completedRounds >= 3`。

轮次不足且没有未消耗种子时，从至少 3 个不连续的内容区域中分散采样至少一个业务单元作为本轮数据集。

## 领域参考

### 种子探查

种子探查可以从以下方向展开，但无需局限于此。错误、正确案例和不同处理方式都可以提供线索：

- **扩展同类**：从错误或正确案例中提取可检索的特征，用 `search_items` 调查其他相似条目。
  - 例如：发现“每日”漏译后，检索 `毎日`，核验其他译文是否保留时间限制。
- **核验差异**：发现同词异译或同类结构处理不同时，调查差异是否符合各自语境。
  - 例如：检索 `先輩`，结合指向对象核验“学长／学姐”的译法。
- **追查关联**：确认新的身份、术语条件或结构关系后，调查受该发现影响的其他条目。
  - 例如：确认别名对应的角色后，检索该别名，复核相关译名与指代。

### 取证与对象判断

- **参与者与上下文**：参与者、身份、指代或上下文衔接不清时，用 `list_items` 的 `after_id` 取相邻条目，再逐个 `read_item` 读取邻近语境；当前工具没有 `queryItemContexts`。
- **姓名与固定译名**：结合人物关系、剧情阶段、身份与 `project_text_policy` 中 `TERM` 规则的适用条件，判断姓名、称谓或固定译名是否适用。
- **原文歧义**：原文存在多种合理解释时，核验译文是否保留原有歧义，以及现有证据是否足以支持收窄解释。
- **证据不足**：无法确定修正时，将结论保留为未决，并说明缺失事实与判断依据。
- **原文材料**：需要核对原稿文本时，用 `list_workspace_materials` 和 `read_workspace_material`；打包 EPUB 是二进制，不能读取内部成员，以导入后的条目为准。

### 人工检查项

以下检查项由审校过程执行，不是工具预生成的警告记录：

|检查项|判断重点|
|---|---|
|漏译与相似度|原文信息与功能是否已表达，是否存在删句、概括或重复|
|外语残留|是否存在局部漏译、浊音、重音或语气词残留|
|保护结构|占位符、标签、控制符、转义和格式结构是否被误翻或破坏|
|术语|术语落实是否正确，当前语境是否符合 `project_text_policy` 中 `TERM` 规则的适用条件|
|标点|标点的结构、位置与作用是否符合原文，是否涉及半边标点或跨条目结构|
|行数与换行|原文与译文的行数是否对齐，换行及跨行结构是否完整|
|姓名与指代|姓名表记、称谓、指向对象和关系阶段是否一致|

### 成果验收

- **调查完整**：实际调查范围与证据相符，每个目标均有修正、保留或未决结论；未决事项说明缺失事实与继续条件。
- **译文成立**：结合原文、译文与必要语境，核验信息完整性、术语适用性、指代与歧义，以及保护结构、标点和换行。
- **修正有据**：每项修改均有对应问题和证据，保留原状的结论有判断依据。
- **结果一致**：`prepare_item_changes` 的方案与最新 `fingerprint` 一致；`item_proposal_status` 回执与实际提交一致。修改或新证据影响其他条目时，复查关联对象并提炼后续种子。
- **规则变更**：需要修改术语或保护规则时，先读取 `project_text_policy`，用 `prepare_text_policy` 提交完整策略替换，并按 `policy_proposal_status` 核对；不要在条目流程中直接改规则。

调查范围尚未覆盖、验收发现遗漏、不一致或待核验事实时，补充或更新种子，继续调查。

## 交付

提供种子账本的可读取位置或内容，并说明：

- 实际调查范围与覆盖程度，区分程序化搜索和逐条语义判断。
- 主要发现、修正或保留的依据，以及未决事项。没有发现问题时，说明检查依据。
- 任务完成或受阻的情况，区分拟议方案、待审批提案与实际提交回执。
- 条目修改数、姓名修改数、规则提案数和剩余未决数量，注明各自统计方法。
