# Native app schema export

`NativeAppDatabase` manages the independent `lnt_native_app.db`, currently **v8 in source**. It owns local project instances, Agent messages/approvals/request receipts, model settings, run journals, translation audit metadata the durable usage ledger and fixed translation tasks/targets. The legacy app database and native `.lnt` project schemas remain separate.

The upgrade chain is registered without destructive fallback:

- 1→2: native chats, messages, approvals, request receipts and model settings.
- 2→3: `native_runs` execution journals.
- 3→4: `native_translation_requests` audit metadata.
- 4→5: explicit protocol and ordered encrypted key envelope.
- 6→7: fixed translation task policies, target fingerprints, request/commit checkpoints and completed membership; source/translation bodies are not copied into the target table.
- 7→8: normalized translation responses and final staged outputs, read by attempt/task only. Valid outputs and usage are recorded together before returning to the engine; stable staged commands support commit recovery without paying again.
- 5→6: `native_usage_receipts`, updated in the same transactions as canonical Agent/translation dispatch and response receipts. It contains no prompt, response, endpoint or credential body. Earlier requests without ledger metadata are not reconstructed or presented as zero cost.
