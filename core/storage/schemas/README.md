# Native app schema export

`NativeAppDatabase` manages the independent `lnt_native_app.db`, currently **v13 in source**. It owns local project instances, Agent messages/approvals/request receipts, Agent input queues/steer ledgers, model settings, run journals, translation audit metadata, the durable usage ledger, fixed translation tasks/targets, and the v8 response/staged-output recovery tables. The legacy app database and native `.lnt` project schemas remain separate.

The upgrade chain is registered without destructive fallback:

- 1→2: native chats, messages, approvals, request receipts and model settings.
- 2→3: `native_runs` execution journals.
- 3→4: `native_translation_requests` audit metadata.
- 4→5: explicit protocol and ordered encrypted key envelope.
- 5→6: `native_usage_receipts`, updated in the same transactions as canonical Agent/translation dispatch and response receipts. It contains no prompt, response, endpoint or credential body. Earlier requests without ledger metadata are not reconstructed or presented as zero cost.
- 6→7: fixed translation task policies, target fingerprints, request/commit checkpoints and completed membership; source/translation bodies are not copied into the target table.
- 7→8: normalized translation responses and final staged outputs, read by attempt/task only. Valid outputs and usage are recorded together before returning to the engine; stable staged commands support commit recovery without paying again.
- 8→9: Agent input queues/drafts and steer run/attempt ledgers; no credentials or model bodies are stored there.

Native `.lnt` is managed by `NativeProjectDatabase`, currently v5 in source (v5 adds per-revision name snapshots); its version upgrades and validation do not use Room. Native project upgrades, Room upgrades and backup restoration each require their own review and evidence.

Explicit termination saves the bound review and receipt in the same transaction as the CANCELLED transition; request/response evidence is retained. The v9→v10 migration is source-only and requires CI/PC generation and migration review.

Room v13 adds `native_agent_branches`, recording command, source/target Chat, selected message and bound digest. Branch creation and message copies are one transaction; approvals, execution ledgers and usage are not copied. The v12→v13 migration and schema export are unverified.
