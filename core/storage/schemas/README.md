# Native app schema export

`NativeAppDatabase` manages the independent `lnt_native_app.db`, currently **v18 in source**. It owns local project instances, Agent messages/approvals/request receipts, Agent input queues/steer ledgers, model settings, run journals, translation audit metadata, the durable usage ledger, fixed translation tasks/targets, and the v8 response/staged-output recovery tables. The legacy app database and native `.lnt` project schemas remain separate.

The upgrade chain is registered without destructive fallback:

- 1→2: native chats, messages, approvals, request receipts and model settings.
- 2→3: `native_runs` execution journals.
- 3→4: `native_translation_requests` audit metadata.
- 4→5: explicit protocol and ordered encrypted key envelope.
- 5→6: `native_usage_receipts`, updated in the same transactions as canonical Agent/translation dispatch and response receipts. It contains no prompt, response, endpoint or credential body. Earlier requests without ledger metadata are not reconstructed or presented as zero cost.
- 6→7: fixed translation task policies, target fingerprints, request/commit checkpoints and completed membership; source/translation bodies are not copied into the target table.
- 7→8: normalized translation responses and final staged outputs, read by attempt/task only. Valid outputs and usage are recorded together before returning to the engine; stable staged commands support commit recovery without paying again.
- 8→9: Agent input queues/drafts and steer run/attempt ledgers; no credentials or model bodies are stored there.

Native `.lnt` is managed by `NativeProjectDatabase`, currently v8 in source (`NativeProjectFormat.SCHEMA_VERSION` in `core/domain/.../TextProject.kt`); its upgrades and validation do not use Room. Native project upgrades, Room upgrades and backup restoration each require their own review and evidence.

Room v10 adds `native_translation_task_decisions` and a task index. Explicit termination saves the bound review and receipt in the same transaction as the CANCELLED transition; request/response evidence is retained. The authoritative schema requires PC/CI generation and migration review.

Room v11 adds `native_translation_member_decisions` with the (task,itemId) primary key. Error retries and explicit keep-error decisions bind individual members and cannot silently replace an earlier disposition. The authoritative schema export and device-upgrade acceptance remain required; current CI coverage belongs in HANDOFF.

Room v12 stores a per-Chat manual context summary and immutable message boundary in `native_agent_contexts`. Full message rows and usage are preserved; model reads and append budgets use the unarchived suffix. 12.json requires KSP export and review; runtime coverage is recorded in HANDOFF.

Room v13 adds `native_agent_branches`, recording command, source/target Chat, selected message and bound digest. Branch creation and message copies are one transaction; approvals, execution ledgers and usage are not copied. The authoritative schema export and device-upgrade acceptance remain outstanding; current CI coverage belongs in HANDOFF.

Room v14 adds persisted item proposals and their members; v15 adds policy proposals; v16 adds PDF-page proposals and page members. v17 adds model profiles and workspace-artifact asset-import proposals, including their command/identity indexes. The migration chain is registered through `MIGRATION_17_18` without destructive fallback.

The current `16→17` migration creates both model-profile and asset-import tables. A database already stamped v17 by an earlier development build will not rerun that migration. `MIGRATION_17_18` now reruns that idempotent additive DDL under a new version, preserving existing rows while creating missing tables/indexes. `NativeAppDatabaseUpgradeTest` covers both missing tables, either missing table, and the complete v17 shape through Room open/validation, with existing context/profile preservation assertions. These cases have not been run locally; authoritative 18.json export and device upgrade validation remain required. No destructive migration is registered.

Native `.lnt` v8 retains the v7 tables and introduces a combined body/name command digest reconstructed from revision snapshots during import validation. Name-target batch writes upgrade through `ensureV8`; old text-only digest bytes remain unchanged. The round-trip and single-revision regression cases are source-only pending PC/CI execution.
