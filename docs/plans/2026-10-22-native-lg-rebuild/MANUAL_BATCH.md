# TXT 人工批量选择与原子写入

本切片对应 R15/R32 的当前页批选、状态修改和清空译文；实施与证据只记入 [HANDOFF §38](HANDOFF.md)。它不授予 Agent 写权限，也不实现全部筛选结果、跨页批选或完整查找替换。查询窗口见 [PROOFREADING_QUERY](PROOFREADING_QUERY.md)。

## 固定选择与确认

校对页显式进入选择模式后，卡片点击和复选框只改变选择，不打开编辑器。选择限定为本页展示的稳定 ItemId，最多 40 条；“选择本页”不包含前瞻行或其他命中页。翻页、重查、刷新和回首页清除普通选择；准备中的预览阻止导航，须先明确关闭。

四种操作为设为未处理、设为已处理、排除、清空译文并设为未处理。前三种保留译文，最后一种有单独警告。prepareBatch 只读一致快照，校验预期修订与全部选中成员，排除已是目标值的条目；没有实际差异不生成成功回执或增加修订。

ManualTextBatch 固定逻辑 commandId、完整 LocalProjectRef、预期修订、操作及目标 ItemId/row/对象指纹。目标集合不可变、有界、去重且升序。预览展示工程、实际修改数量、操作和最多十个原稿行号；选择和准备均不写工程，只有单独确认调用 editBatch。确认和关闭携带预览固定 payload，执行层拒绝旧预览对新批次的迟到确认/关闭。

## 原子写入与 v1 回执

调用链：`NativeProjectViewModel.confirmManualBatch → NativeTextProjectStore.editBatch → ProjectWriteStore.editBatch`。先取得既有人工 Runtime 写租约，再在同一外层 SQLite 事务内核对全批修订/成员/指纹，之后逐条走既有编辑、对象指纹、item_revisions 和 write_receipts。每个实际修改增加一个修订；冲突拒绝整批，取消/异常回滚全部，不能部分成功。模型/Agent 运行时不能取得人工写租约。

不修改 `.lnt` v1 schema 或导入校验。每条成功回执仍保存普通 ManualTextEdit 的标准 64 位摘要，与历史内容一致。批次全量 payload 摘要绑定在生成的子命令 ID：`manual-batch-v1:<logicalCommandHash>:<payloadHash>:<index>`。哈希由 UTF-8 SHA-256 生成，原始命令不拼入 SQL 模式；按实例/代际及生成前缀核对已有组回执。

同一逻辑命令只对应一套 payload。已有回执必须数量完整、子命令匹配、条目/状态/修订序列一致；操作、目标或基线变化不能复用旧命令。部分或碰撞回执直接拒绝，不补写余项；单条和批量逻辑命令不能互相复用。

冲突持久保存整批拒绝回执。重复确认已提交/拒绝的批次只返回原结果，不覆盖后来的修改。确认响应丢失时，保留同一 payload/commandId，用户可显式核对或重试；不自动生成新命令，不把未知状态当作回滚。

## 界面恢复与错误

预览通过有版本、长度/数值/排序校验的 SavedStateHandle 元数据恢复，只含身份、操作、修订和指纹，不含正文。重建只恢复匹配完整工程身份的预览并返回校对页，仍需明确确认；不是完整持久任务恢复，不在启动时自动提交。冲突预览禁用确认，提示关闭、刷新后重新准备。

已知提交后保留查询窗口成员及顺序，再重读最新值和统计；显式重查才重选。读取失败保留提交预览/修订、清空失效统计，并明确提示“批次已应用，页面刷新失败”。核对旧成功回执时，不用旧预览覆盖界面已读取的较新修订。
