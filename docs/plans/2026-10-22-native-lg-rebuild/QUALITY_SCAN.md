# 已保存 TXT 译文的质量扫描与筛选

源码进度与验证边界见 [HANDOFF §46](HANDOFF.md)。单条算法继续由 [TEXT_QUALITY](TEXT_QUALITY.md) 定义；本切片没有补齐 LG 的字素、姓名/PDF、多格式智能保护或全部质量规则。

## 读取与发布

`NativeQualityPanel → NativeProjectViewModel.scanQuality → ProjectQualityScanner → TextProjectPort.items / ProjectTextPolicyPort.textPolicy`。

用户显式选择检查语言并启动；遍历整个当前工程，按当前状态、字面文本及原/译字段查询确定检查范围。只检查已保存条目，编辑草稿须先关闭。未保存规则、规则读取失败、批选/审批草稿、运行任务和其他 busy 操作阻止启动。每 20 条读取一次；读取全部正文只存在于该页及单条检查的后台计算中，不把原稿/译文放入全工程索引。

开始固定 Project/Instance/Generation、全局修订、查询、规则指纹和语言。每页读取核对相同修订、ID 严格递增、数量与工程总数；末尾再读修订。规则编译在单次检查器中复用，单条工作预算仍单独创建。所有计算在 Default 运行，存储适配器自行切 IO；每页提供轻量进度，允许取消。工程变化、读取失败、规则错误、取消和预算超限不发布部分结果，不把未完成扫描显示为无警告。

默认预算：最多 100,000 条，原译累计 16,777,216 UTF-16 单元，警告代码与缺失术语命中合计最多 250,000 项；任一超限整次失败。它们是源码约束，不是设备容量或性能验收。单条预算继续按 TEXT_QUALITY。没有模型调用、数据库写入、任务执行接续或持久质量缓存。

## 索引与统计

TextQualityIndex 只保留条目 ID/指纹、评估状态、固定词表代码和缺失术语规则 ID，绑定完整快照身份。统计按当前状态/文本查询的完整范围计算，不限当前显示页：

- 全部匹配、未评估、已评估无提示、任意提示分开；未处理/排除/空白译文不计入“无提示”。
- 同条目每种警告只计一次；不同警告可同时计入，所以类型计数相加可以超过有提示条目数。
- 术语按缺失规则 ID 去重计数；选择某术语与 GLOSSARY 提示共同筛选。

筛选先形成稳定有序 ID 选择，再用至多 41 个 ID 读取 40 条页面及后一条探测。固定窗口读取重新核对全局修订、完整成员及各指纹；空选择返回空页，不退回全部条目。前后翻页不重新扫描正文；筛选控件只是草稿，点击应用后才改变列表。所有大列表继续使用 LazyColumn 和稳定 key。

索引只在内存持有，不进入 SavedStateHandle、Room 或 `.lnt`。关闭结果、改变基本查询、显式刷新/打开工程或进程重建后回到普通查询；新扫描失败时不覆盖上一份完整结果。修改条目/批量状态/规则后保留当前固定成员及已提交事实，但旧索引标记失效，隐藏旧统计/行提示并禁止其翻页与筛选，须重新扫描或关闭结果。规则保存后的固定窗口刷新不把正常索引失效冒充规则读取失败。索引存在时禁止启动按页/整工程翻译，避免把质量筛选成员误作普通翻译范围。

页面新增五语扫描/筛选对话窗、计数、进度与失效提示；顶部控件可在有限高度内滚动，给小视口保留条目列表空间。没有录制或查看新增原生界面截图，不能据静态布局认定视觉通过。
