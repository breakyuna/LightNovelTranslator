## 工程事实与 v1/v2 边界

历史规则切片使用 schema v2；当前新建工程使用 schema v3，保持原 application_id、TXT 原始字节、条目身份、既有指纹/命令编码及旧库隔离；新增 text_policy、policy_revisions 和 policy_receipts。独立应用 Room 为 v4，已有 §49 CI；规则切片不新增 Room 版本，也不手写导出 schema。

v1 工程可继续读取、人工编辑、导出和重导入；只读规则查询返回空规则，不改文件版本。首次规则写入由 ProjectWriteStore 在同一写事务中检查 v1 schema、增加规则表、初始化空策略并更新 user_version=2；规则、全局工程修订、历史和终局回执一并提交。取消/异常回滚升级和业务数据。被拒绝写入仍保存不可变拒绝回执，因此也会进入 v2；未来版本或未知 schema 拒绝，不破坏性清库。

规则包含稳定 ID、四种类型、源/目标/备注、启用、字面/正则及大小写标志；列表顺序是事实。工程提示词有独立启用开关。单次读取得到同事务工程修订和规则指纹，所有编辑通过 ProjectTextPolicyPort → NativeTextProjectStore → ProjectWriteStore，受真实 Runtime 人工写租约约束；模型运行期间不能改规则。

命令绑定 Project/Instance/Generation、预期全局修订、原规则指纹及完整新规则指纹。已提交或拒绝的命令返回原回执，改变 payload 拒绝；规则与单条/批量条目不能复用命令身份。当前编辑整体规则快照，不提供 Agent 多对象审批授权。

规则与条目共用全局修订号，条目历史可因规则提交出现合法间隙。导入验证两类历史合并后连续、各自对象链连续、规则 payload/指纹/命令摘要一致、成功回执完整且无跨类型命令碰撞。快照按实际源版本创建表并复制全部规则历史；v1 快照不会冒充 v2，复制/重导入生成新本地实例且不继承可执行授权。

## 本次规则处理语义

远程翻译在唯一运行租约内读取一次规则快照，核对工程身份与预期修订，整个当前页/整工程运行固定该快照。缺少规则端口、读取失败或修订不符时，不静默退回空规则。显式本地模拟保持原测试语义，不执行项目规则或提示词。

1. 在原始条目中匹配所有已启用术语，按大小写设置挑选源/目标/备注加入该条请求，不取固定首条规则。
2. 匹配自定义文本保护：先取最早源位置，同起点按规则顺序；后续重叠范围跳过。非空匹配替换为本次唯一 token，不让模型修改原始控制文本。
3. 按顺序在非保护区域执行译前替换，再按转换后的长度规划每批字符预算。保护展开/替换超出硬预算或转换为空白时，在请求前拒绝，不发起无内容付费请求。
4. 请求包含规则指纹、已启用工程提示词及本次翻译要求；条目 ID/对象指纹仍绑定原始条目。模型须完整返回每个保护 token 一次。
5. 响应协议校验成功后，对非保护区域执行译后替换，核对 token 的缺失/重复/伪造并恢复原字面保护文本，再经既有批事务提交。任一条规则处理失败不提交本批；之前批次保留，已收响应 Token 沿用 §43 回执。

保护区域对译前/译后替换都不可见；替换不会跨保护边界。该选择优先保留原始结构，尚未完成 LG 所有保护/替换组合的黄金差异验收。术语为正文命中提示，尚无姓名字段/术语应用告警或全部格式智能保护。

## 正则与预算

新增 catalog 依赖 `com.google.re2j:re2j:1.8`，domain 以 api 暴露同一匹配实现，engine/storage 不另建平台正则旁路。选择依据为 [官方项目说明](https://github.com/google/re2j) 的非回溯算法和 [1.8 发布记录](https://github.com/google/re2j/releases/tag/re2j-1.8) 的 Java 风格命名捕获支持；逐符号核对 [Pattern](https://github.com/google/re2j/blob/re2j-1.8/java/com/google/re2j/Pattern.java)、[Matcher](https://github.com/google/re2j/blob/re2j-1.8/java/com/google/re2j/Matcher.java) 和 [MatcherInput](https://github.com/google/re2j/blob/re2j-1.8/java/com/google/re2j/MatcherInput.java)。这些不是依赖解析、Android D8/R8、设备或实际性能证据。

当前正则是明确的 RE2 子集：支持命名/数字捕获、Unicode 文本和大小写匹配；不支持环视、模式内反向引用和本切片排除的 x/U 内联模式，不改写其含义或回退到平台 Matcher。替换支持反斜杠数字、g<名称或数字>、n/r/t 和转义反斜杠；美元引用为字面量，缺失捕获为空。名称通过编译器的组序号表访问，不使用 Android API 26 的平台命名组接口。

规则最多 256 条，单源/目标最多 4096 字符、备注 2048、提示词 16384；完整原生规则 JSON 最多 65536 字符。正则嵌套深度 32、捕获组 128、单程序 8192 指令、已启用规则总程序 65536 指令。单条保护匹配最多 4096，单条处理共享 400 万次受控字符访问预算；输入与输出仍受 65536 字符硬预算约束，并检查协程取消。以上是实现预算，尚无目标设备容量或延迟测量，不能声称完整 LG 正则兼容。

## 原生规则页与草稿

同工程导航新增“规则与提示词”页，四类规则可添加、编辑、删除、启停和上下排序；大列表使用稳定 ID 的 LazyColumn，列表 key 与固定页面条目分开。规则编辑/JSON 导入为固定窗口、有界滚动和固定按钮；正则编译、导入解析在后台执行，错误定位规则 ID且不回显异常正文。

草稿绑定完整工程实例/代际、原修订和指纹，使用有界 SavedStateHandle 元数据保留规则草稿及原命令；重建时先按原命令/完整摘要只读核对：已提交则重读当前最新规则并清除旧草稿，不用旧内容覆盖后续修改；拒绝回执保留冲突。未有回执而工程已变化时保留草稿并标冲突，不自动重新绑定。切页保留草稿，回首页须明确放弃；保存前不改工程，未保存/读取失败阻止 UI 翻译启动。提交后刷新失败提示已保存事实并阻止后续编辑，重载后再操作。

原生 JSON 导入经过显式预览，应用仅替换本地草稿，另按保存才写工程；复制 JSON 明确复制当前草稿到剪贴板。格式名为 lnt-text-policy/version 1，不接收未知字段/重复 ID/错误类型，不冒充 LG 预设/CSV 交换，也不是系统文件导入导出。工程导出则已包含已提交规则。
